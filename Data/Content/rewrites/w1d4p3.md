# Week 1 - Day 4 - Implementation - Proving the `.spec.ts` naming convention

In [Fundamentals](/learn/w1/d4/p2), you read that Playwright ignores a test file whose name does not
end in `.spec.ts`. In this lesson, you prove it in your own project: you create a correct test file
with the wrong name, watch Playwright ignore it, and then rename it.

You do every step in VS Code and in its integrated terminal, in the project that you created in
[Day 2 - Fundamentals](/learn/w1/d2/p2).

## Step 1: Create a test file with the wrong name

Create a file named `not-a-spec.ts` in the `tests` folder:

1. In the **Explorer** panel on the left of VS Code, right-click the `tests` folder and select
   **New File**.
2. Type `not-a-spec.ts` and press Enter. The empty file opens.
3. Paste the test below into it, and press **Ctrl+S** to save. A file that is not saved is not run.

Every word in this code is explained in [Day 5 - TypeScript](/learn/w1/d5/p1) and
[Day 5 - Fundamentals](/learn/w1/d5/p2). For now, copy it as written:

```ts
import { test, expect } from '@playwright/test';

test('the login page shows an email field', async ({ page }) => {
  await page.goto('https://test-automation-banking.vercel.app/');
  await expect(page.getByPlaceholder('Enter Email')).toBeVisible();
});
```

**Explanation:** The test is correct: it opens the banking website and checks that the email field
is visible. Only the file name is wrong, because it ends in `.ts` instead of `.spec.ts`.

## Step 2: List the tests that Playwright can see

The `--list` option makes Playwright list the tests that it would run, without running them. In the
terminal, run:

```bash
npx playwright test --list
```

**Output**

```output
Listing tests:
  [chromium] › example.spec.ts:3:5 › has title
  [chromium] › example.spec.ts:10:5 › get started link
  [firefox] › example.spec.ts:3:5 › has title
  [firefox] › example.spec.ts:10:5 › get started link
  [webkit] › example.spec.ts:3:5 › has title
  [webkit] › example.spec.ts:10:5 › get started link
Total: 6 tests in 1 file
```

**Explanation:** The list contains only the two tests from `example.spec.ts`, once for each browser.
The new test is missing, although its file is in the `tests` folder and its code is correct.
Playwright shows no error and no warning about it.

## Step 3: Rename the file

In the Explorer panel, right-click `not-a-spec.ts`, select **Rename**, change the name to
`not-a-spec.spec.ts`, and press Enter. Then run the same command again:

```bash
npx playwright test --list
```

**Output**

```output
Listing tests:
  [chromium] › example.spec.ts:3:5 › has title
  [chromium] › example.spec.ts:10:5 › get started link
  [chromium] › not-a-spec.spec.ts:3:5 › the login page shows an email field
  [firefox] › example.spec.ts:3:5 › has title
  [firefox] › example.spec.ts:10:5 › get started link
  [firefox] › not-a-spec.spec.ts:3:5 › the login page shows an email field
  [webkit] › example.spec.ts:3:5 › has title
  [webkit] › example.spec.ts:10:5 › get started link
  [webkit] › not-a-spec.spec.ts:3:5 › the login page shows an email field
Total: 9 tests in 2 files
```

**Explanation:** Nothing inside the file changed. Only its name did, and now Playwright finds the
test and lists it once for each browser. A name that ends in `.test.ts` works in the same way.

## Step 4: Clean up

In the Explorer panel, right-click `not-a-spec.spec.ts` and select **Delete**, so that your project
contains only the example tests again.

## Why this matters

Most mistakes in a test show up as a failure. A wrongly named file shows up as nothing at all: every
run passes, because the test never runs. When a test seems to have disappeared, run
`npx playwright test --list` and count what Playwright can see.

## What a reviewer looks for

- Every test file ends in `.spec.ts`.
- When a test seems to be missing, the reviewer lists the tests before reading any code.
