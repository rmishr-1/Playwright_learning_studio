# Week 1 - Day 2 - Fundamentals - Environment setup & your first Playwright project

Before you can write a test, your computer needs three things: Node.js, a code editor, and a
Playwright project. In this lesson, you install the first two and create the third.

## Step 1: Open a terminal

A **terminal** is a program in which you type commands for your computer to run. You type a
command, press Enter, and the result appears below it.

| Operating system | How to open a terminal |
|---|---|
| Windows | Open the Start menu, type **PowerShell**, and select **Windows PowerShell**. |
| macOS | Press Command and Space, type **Terminal**, and press Enter. |
| Linux | Open the application menu and select **Terminal**. |

## Step 2: Install Node.js

**Node.js** is a program that runs JavaScript and TypeScript code outside a web browser. Playwright
runs on Node.js. Installing Node.js also installs **npm**, a tool that downloads **packages**: code
that other people have written and shared, such as Playwright itself.

To check whether Node.js and npm are installed, run these two commands in the terminal:

```bash
node -v
npm -v
```

**Output**

```output
v22.12.0
10.9.0
```

**Explanation:** Each command prints a version number. Your numbers will be different, which is
expected. Playwright needs Node.js version 20 or later, so the first number must be 20 or higher.

If the terminal reports that `node` is not recognized, Node.js is not installed yet. Download the
**LTS** version from https://nodejs.org and install it. LTS stands for long-term support: the
version that receives updates for the longest time. Then close the terminal, open a new one, and
run the two commands again.

## Step 3: Install Visual Studio Code

**Visual Studio Code**, usually called **VS Code**, is a free code editor from Microsoft. A **code
editor** is a program for writing and editing code. Download it from https://code.visualstudio.com
and install it.

You use three features of VS Code throughout this course:

| Feature | How to use it | Why it matters |
|---|---|---|
| Open Folder | Select **File**, then **Open Folder**, and choose your project folder. | VS Code then treats everything in that folder as one project. |
| Trust the folder | When VS Code asks whether you trust the authors of the files, select **Yes, I trust the authors**. | VS Code turns off some features in a folder until you trust it. |
| Integrated terminal | Select **View**, then **Terminal**. | This opens a terminal inside VS Code that already points at your project folder. |

## Step 4: Create your Playwright project

A **project** is a folder that contains your tests and the settings that Playwright needs to run
them. To create one:

1. Create an empty folder named `playwright-course`, for example in your Documents folder.
2. In VS Code, open the folder, and trust it when asked.
3. Open the integrated terminal, and run this command:

```bash
npm init playwright@latest
```

The command asks four questions. Answer them as follows:

| Question | Your answer |
|---|---|
| Do you want to use TypeScript or JavaScript? | **TypeScript** |
| Where to put your end-to-end tests? | **tests**, the suggested answer |
| Add a GitHub Actions workflow? | **No**. GitHub Actions runs tests on a server, which this course does not need. |
| Install Playwright browsers? | **Yes** |

On Linux, the command also asks whether to install the system packages that the browsers need.
Answer **Yes**.

**Output**

The last lines look similar to this:

```output
Inside that directory, you can run several commands:

  npx playwright test
    Runs the end-to-end tests.

We suggest that you begin by typing:

    npx playwright test

And check out the following files:
  - ./tests/example.spec.ts - Example end-to-end test
  - ./playwright.config.ts - Playwright Test configuration
```

**Explanation:** The command installs Playwright into your folder and downloads the three browsers
that it tests with. It then writes the files described in the next section. It can take a few
minutes, because the browsers are large downloads.

> **Important:** **Run this command only in a new, empty folder.** In a folder that already
> contains a Playwright project, it can replace the existing configuration file.

## What the command creates

Your folder now contains these files and folders:

```text
playwright-course/
  node_modules/          the packages npm installed, including Playwright
  tests/
    example.spec.ts      an example test file that checks the Playwright website
  .gitignore             the list of files that Git should not save
  package.json           the list of packages that your project uses
  package-lock.json      the exact version of every installed package
  playwright.config.ts   the settings Playwright reads each time it runs your tests
```

You never edit `node_modules/` or `package-lock.json` by hand, because npm manages them for you.
[Implementation](/learn/w1/d2/p3) explains `.gitignore` and how to organize your tests.

## A first look at the configuration file

`playwright.config.ts` is the **configuration file**: it holds the settings for every test run.
Open it in VS Code. Without its comments, the main part looks like this:

```ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  fullyParallel: true,
  reporter: 'html',
  use: {
    trace: 'on-first-retry',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox', use: { ...devices['Desktop Firefox'] } },
    { name: 'webkit', use: { ...devices['Desktop Safari'] } },
  ],
});
```

Three settings are worth recognizing now:

| Setting | What it means |
|---|---|
| `testDir: './tests'` | Playwright looks for test files in the `tests` folder. |
| `reporter: 'html'` | After each run, Playwright creates a report that you open in a browser. |
| `projects` | The browsers that each test runs in. Here, every test runs in Chromium, Firefox, and WebKit. |

[Day 3 - Implementation](/learn/w1/d3/p3) explains every setting in the file.

## Best practices

- Run `npm init playwright@latest` only in a new, empty folder, so that it cannot replace an
  existing configuration file.
- Always open your project folder in VS Code before you run a command, so that the command runs in
  the right place.
- Keep the answers suggested in this lesson. Later lessons assume a TypeScript project with its
  tests in the `tests` folder.

## Common mistakes

| Mistake | What you see | Fix |
|---|---|---|
| Opened the terminal before installing Node.js | `node` is not recognized | Close the terminal and open a new one. |
| Answered **No** to installing the browsers | Later, `browserType.launch: Executable doesn't exist` | Run `npx playwright install` in your project folder. |
| Ran the command in the wrong folder | The files appear in an unexpected place | Open the correct folder in VS Code, and run the command again there. |
