# Week 1 - Day 5 - TypeScript - Arrow functions, `async`, and reading `import`

Every Playwright test is written in **TypeScript**, a programming language that adds types to
JavaScript. This lesson teaches the parts of TypeScript that every test uses. By the end of it, you
will be able to:

- store a value in a variable, and print it
- write a function, and an arrow function
- explain what `async` and `await` do
- read the first two lines of every test file

## How to run the examples

Select **Load into editor** on an example, then select **Run**. The **Console** tab below the editor
shows everything that the code prints. Each run starts from the beginning, so a value from an earlier
run is never kept.

## Values, variables, and `console.log`

A **value** is a piece of data, such as the number `25` or the text `'Leela'`. A piece of text is
called a **string**, and it is written between quotes. A **variable** is a name that holds a value.
You create one with `const`, which means that the name always holds the same value.

In TypeScript, you can also state the **type** of a variable, meaning the kind of value it holds.
`: string` means text, and `: number` means a number. `console.log` prints a value in the Console
tab.

The example below creates two variables and prints them:

```ts
const name: string = 'Leela';
const age: number = 30;

console.log(name);
console.log(age + 1);
console.log(`Hello, ${name}`);
```

**Output**

```output
Leela
31
Hello, Leela
```

**Explanation:** `age + 1` is calculated before it is printed, so the Console shows `31`. The last
string is written between backticks (`` ` ``) instead of quotes. A string in backticks can include
the value of a variable with `${...}`, so `${name}` becomes `Leela`.

## Functions and arrow functions

A **function** is a named set of steps that you can run as often as you need. A function can take
**parameters**, which are the values you give it, and it can **return** a result. Running a function
is also called **calling** it.

An **arrow function** is a short way to write a function, with `=>` between the parameters and the
steps. Every test that you write is an arrow function.

The example below creates two arrow functions and calls them:

```ts
// One step, without braces: the result is returned automatically.
const square = (n: number) => n * n;

// Several steps, inside braces: you write return yourself.
const greet = (name: string) => {
  const message = `Hello, ${name}`;
  return message;
};

console.log(square(5));
console.log(greet('Leela'));
```

**Output**

```output
25
Hello, Leela
```

**Explanation:** `square` takes one parameter, `n`, and returns `n * n`. Without braces, the result of
the single step after `=>` is returned automatically. `greet` has braces, because it has more than one
step, so it needs the word `return` to give back its result. Without `return`, it would give back
nothing.

## `async` and `await`

Some steps take time to finish, such as opening a web page or selecting a button. A function that
starts such a step returns a **Promise**, which is a value that stands for a result that is not ready
yet. Every Playwright action, such as `goto`, `fill`, and `click`, returns a Promise.

`await` tells the code to wait until a Promise is ready before it goes on to the next line. You can use
`await` only inside a function marked `async`. In the editor, you can also use `await` outside a
function, as the examples in [Day 4 - Fundamentals](/learn/w1/d4/p2) did.

The example below waits one second before it returns a greeting:

```ts
// wait() returns a Promise that is ready after the given number of milliseconds.
const wait = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms));

const slowGreet = async (name: string) => {
  await wait(1000);
  return `Hello, ${name}`;
};

console.log('Before');
console.log(await slowGreet('Katy'));
console.log(slowGreet('Katy'));
console.log('After');
```

**Output**

```output
Before
Hello, Katy
Promise { <pending> }
After
```

**Explanation:** You do not need to know how `wait` is built. It stands for any step that takes time,
as Playwright's actions do. The second line waits for `slowGreet`, so it prints the greeting after one
second. The third line calls `slowGreet` without `await`, so it prints the Promise itself, which is
still `<pending>`, meaning not ready. A Playwright action without `await` behaves in the same way: the
next line starts before the action has finished.

## Objects and destructuring

An **object** groups several named values together, between braces. Each named value is a
**property**. You read a property with a dot, so `user.name` is the `name` property of `user`.

**Destructuring** takes properties out of an object by name. You can destructure in the parameters of
a function, by writing the names you need between braces.

The example below destructures a user in the parameters of a function:

```ts
const user = { name: 'Leela', email: 'leela@gmail.com' };
console.log(user.name);

// Take name and email out of the object that the function receives.
const describeUser = ({ name, email }: { name: string; email: string }) =>
  `${name} <${email}>`;

console.log(describeUser(user));
```

**Output**

```output
Leela
Leela <leela@gmail.com>
```

**Explanation:** `user` is an object with two properties. `describeUser` receives the whole object,
and `{ name, email }` takes out the two properties it needs, so the function can use `name` instead of
`user.name`. The part after the colon, `{ name: string; email: string }`, is the type of the object:
it says which properties the object has, and what kind of value each one holds.

Every test uses this shape. Playwright gives each test an object of tools, called **fixtures**, and
the test takes out the one it needs, which is usually `page`:

```ts
test('the login page opens', async ({ page }) => {
  // Use page here.
});
```

The test is an arrow function. It is marked `async` because it uses `await` for Playwright's actions,
and `({ page })` takes the `page` fixture out of the object that Playwright gives it.

## Reading `import`

A **package** is code that someone else wrote and published, and that npm installs in your project.
You met `package.json`, which lists your project's packages, in
[Day 3 - Fundamentals](/learn/w1/d3/p2). An `import` line takes named values out of a package, so
that your file can use them.

Every test file in your project starts with this line:

```ts
import { test, expect } from '@playwright/test';
```

**Explanation:** The line takes two values, `test` and `expect`, out of the package
`@playwright/test`. `test` creates a test, and `expect` checks a result.
[Fundamentals](/learn/w1/d5/p2) uses both. The editor here provides `launch()` and `show()` for you,
so you write this line only in the test files in your own project.

## Common mistakes

| Mistake | What you see | Fix |
|---|---|---|
| Used braces without `return` | The function gives back `undefined`, which means no value | Add `return`, or remove the braces for a single step. |
| Left out `await` before a step that takes time | A `Promise { <pending> }`, or the next step runs too early | Put `await` before the step. |
| Used `await` in a function without `async` | An error saying that `await` is only allowed in async functions | Put `async` before the parameters of the function. |
