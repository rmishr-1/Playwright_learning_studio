# Week 1 - Day 5 - Implementation - The same login, with a little structure

Both tests in [Fundamentals](/learn/w1/d5/p2) repeat the same sign-in steps. In this lesson, you place
those steps in one piece of code, called a **page object**, which every test can use. You do every
step in VS Code and in its integrated terminal, in your own project.

## Why repeated steps are a problem

Imagine fifty tests that each find the email field with `page.getByPlaceholder('Enter Email')`. If
the website changes the placeholder text, you have to change the same line in fifty places. If the
line is written once, in one place, you change it once.

## Classes, in brief

A **class** is a template for an object. It lists the properties that each object made from it has,
and the functions that it can run. A function that belongs to a class is called a **method**. Four
words appear in every class that this course uses:

| Word | What it means |
|---|---|
| `constructor` | A method that runs once, when an object is made from the class. It sets the properties. |
| `this` | The object itself, inside its own methods. `this.page` is the object's `page` property. |
| `new` | Makes an object from a class, as in `new LoginPage(page)`. |
| `readonly` | Marks a property that is set once in the constructor, and never changed afterwards. |

## Step 1: Create the test file

In the `tests` folder, create a file named `login-page.spec.ts`, as in
[Day 4 - Implementation](/learn/w1/d4/p3), and paste this code into it:

```ts
import { test, expect, type Locator, type Page } from '@playwright/test';

// The sign-in steps, written once. The class checks nothing: the tests decide what is correct.
class LoginPage {
  readonly page: Page;
  readonly emailField: Locator;
  readonly passwordField: Locator;
  readonly loginButton: Locator;

  constructor(page: Page) {
    this.page = page;
    this.emailField = page.getByPlaceholder('Enter Email');
    this.passwordField = page.getByPlaceholder('Enter Password');
    this.loginButton = page.getByRole('button', { name: 'Login' });
  }

  async signIn(email: string, password: string) {
    await this.page.goto('https://test-automation-banking.vercel.app/');
    await this.emailField.fill(email);
    await this.passwordField.fill(password);
    await this.loginButton.click();
  }
}

test('a correct password opens the dashboard', async ({ page }) => {
  const loginPage = new LoginPage(page);
  await loginPage.signIn('leela@gmail.com', 'Leela@123');
  await expect(page).toHaveURL(/dashboard/);
  await expect(page.getByText('Leela')).toBeVisible();
});

test('a wrong password shows an error message', async ({ page }) => {
  const loginPage = new LoginPage(page);
  await loginPage.signIn('leela@gmail.com', 'WrongPassword1');
  await expect(page.getByText('Please Enter Valid Credentials')).toBeVisible();
});
```

**Explanation:** `Page` and `Locator` are the types of a browser tab and of a locator. The word
`type` in the `import` line means that the file uses them only as types. The constructor finds the
three elements once, and stores each locator in a property. `signIn` is a method that performs the
sign-in steps with the email and password it is given. Each test makes its own `LoginPage` with
`new`, calls `signIn`, and then makes its own assertions.

## Step 2: Run the tests

In the integrated terminal, run:

```bash
npx playwright test tests/login-page.spec.ts --project=chromium
```

**Output**

```output
Running 2 tests using 2 workers
  2 passed (7.4s)
```

**Explanation:** Both tests used the same `signIn` method, and both passed. One test expected the
dashboard, and the other expected the error message. Your time and your number of workers may be
different.

## Why the class contains no assertions

The class performs the steps, and the tests decide what the correct result is. That is why one class
serves both tests here, although they expect opposite results. If `signIn` checked for the dashboard
itself, the second test could not use it, because a wrong password never opens the dashboard.

A class like this one is called a page object, and a set of page objects for a website follows the
**Page Object Model**. A later lesson covers it in full.

## What a reviewer looks for

- Each locator is written once, in the constructor of the page object.
- Methods are named for what a user does, such as `signIn`.
- The page object performs steps, and the tests make every assertion.
