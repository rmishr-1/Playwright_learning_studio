# Week 2 - Day 1 - Fundamentals - From recorder to real code: actions on a form

In Week 1, every action you wrote was `fill()` or `click()` on a login form with two fields. In this
lesson, you fill a whole registration form by hand: text fields, a radio button, checkboxes, and two
dropdowns. Then you write the same actions as a test in your own project, and end it with an
assertion.

## The registration form

This lesson uses a practice page at
[demo.automationtesting.in/Register.html](https://demo.automationtesting.in/Register.html). It is
a registration form with no account behind it. Nothing you type is saved, so you can fill it as
often as you like. Selecting **Submit** on this page shows no confirmation message. The address
stays the same, and the fields keep their values. For that reason, the checks in this lesson look at
the fields themselves.

The form has three kinds of control that the login form did not have:

- A **radio button** is a small circle in a group, such as Male and FeMale under Gender. Selecting
  one clears the others, so a group holds one choice at a time.
- A **checkbox** is a small square, such as Cricket, Movies, and Hockey under Hobbies. Each one is
  on or off by itself, so you can check several.
- A **dropdown** is a list that opens when you select it, such as Skills and Select Country. You
  pick one of its options.

**Note:** The page spells the second gender option **FeMale**, with a capital M. The examples below
use the spelling that the page uses.

## Finding controls that have no label or placeholder

[Week 1 - Day 4 - Fundamentals](/learn/w1/d4/p2) introduced `getByPlaceholder`, `getByRole`, and
`getByLabel`. On this form, First Name and Last Name have placeholder text, and the two gender
radio buttons have labels. The other controls have no label, no placeholder, and no visible name,
so you need one more way to find an element.

An **attribute** is a name and a value written inside a tag, such as `type='email'` inside an
`<input>` tag. An **id** is an attribute that gives one element a name that no other element on the
page shares, such as `id="checkbox1"`.

`page.locator()` finds an element by a **CSS selector**, a short piece of text that describes an
element by its tag, its id, or one of its attributes:

| Selector | What it finds | Example on this form |
|---|---|---|
| `tag` | Every element with that tag | `page.locator('textarea')`, the Address field |
| `#id` | The element with that id | `page.locator('#checkbox1')`, the Cricket checkbox |
| `tag[attribute='value']` | Every element with that tag and that attribute value | `page.locator("input[type='email']")`, the Email field |

This form has one `<textarea>`, one `<input>` whose `type` is `email`, and one whose `type` is
`tel`, so each of those selectors finds exactly one element. Prefer a placeholder, a role, or a
label whenever a control has one. They describe what a user sees, and they keep working when the
page's markup changes. A selector describes the markup itself.

## Text fields: fill()

`fill()` puts a value into a text field in one step. It clears whatever the field held, and then
sets the new value. The example below fills the five text fields at the top of the form. Select
**Load into editor**, then select **Run**:

```ts
const { browser, page } = await launch();
await page.goto('https://demo.automationtesting.in/Register.html');

// Fill the two name fields by their placeholder text.
await page.getByPlaceholder('First Name').fill('Ada');
await page.getByPlaceholder('Last Name').fill('Lovelace');

// Fill the three fields that have no placeholder, by tag and by attribute.
await page.locator('textarea').fill('12 Engine Street');
await page.locator("input[type='email']").fill('ada@example.com');
await page.locator("input[type='tel']").fill('5551234567');

// Show a screenshot, then close the browser.
await show(page);
await browser.close();
```

**Output**

A screenshot of the form appears beside the editor, with Ada, Lovelace, the address, the email,
and the phone number in their fields.

**Explanation:** Each line finds one field and sets its value. The Address field has no placeholder
and no label, so the selector names its tag, `textarea`. The Email and Phone fields are both
`<input>` tags, so the selector names the attribute that tells them apart. `fill()` replaces the
value, so running the same line twice leaves the field with one copy of the text, not two.

## Typing one key at a time: pressSequentially()

Some fields react to each key that a user presses. A search box that shows suggestions after every
letter is one example. `fill()` sets the value in one step, so such a field never sees a keystroke
and never reacts. `pressSequentially()` sends one key at a time, as a person typing would. The
example below types the phone number with a pause after each digit:

```ts
const { browser, page } = await launch();
await page.goto('https://demo.automationtesting.in/Register.html');

// Type the phone number one key at a time, with a pause of 100 milliseconds after each key.
await page.locator("input[type='tel']").pressSequentially('5551234567', { delay: 100 });

// Print the value that the field holds now.
console.log(await page.locator("input[type='tel']").inputValue());

await show(page);
await browser.close();
```

**Output**

The Console tab shows `5551234567`, and the screenshot shows the number in the Phone field.

**Explanation:** `inputValue()` returns the text that a field holds. The result is the same as with
`fill()`, because this field does nothing special on each key. Use `fill()` unless a field reacts to
each keystroke, because `fill()` does one step where `pressSequentially()` does one step per
character.

**Note:** Older code and older tutorials write `.type()` for the same job. `pressSequentially()` is
the current name, and VS Code draws a line through `type` to show that it is out of date.

## Radio buttons and checkboxes: check()

`check()` makes a radio button or a checkbox checked. If the control is already checked, `check()`
leaves it as it is. The example below checks one gender and two hobbies:

```ts
const { browser, page } = await launch();
await page.goto('https://demo.automationtesting.in/Register.html');

// Check the radio button whose label reads FeMale, as the page spells it.
await page.getByLabel('FeMale').check();

// Check two of the hobby checkboxes by their ids.
await page.locator('#checkbox1').check();
await page.locator('#checkbox3').check();

await show(page);
await browser.close();
```

**Output**

The screenshot shows FeMale selected under Gender, and Cricket and Hockey checked under Hobbies.

**Explanation:** The text FeMale is written inside a `<label>` tag that wraps the radio button, so
`getByLabel` finds it. The text next to each checkbox is not connected to it, so the checkboxes need
their ids: `checkbox1` is Cricket, `checkbox2` is Movies, and `checkbox3` is Hockey. Two hobbies
stay checked because checkboxes are independent. Checking Male afterwards would clear FeMale,
because radio buttons in one group hold one choice.

## Dropdowns: selectOption()

`selectOption()` picks one option in a dropdown, by the text of the option. The example below picks
a skill and a country:

```ts
const { browser, page } = await launch();
await page.goto('https://demo.automationtesting.in/Register.html');

// Pick one option in each dropdown, by the text of the option.
await page.locator('#Skills').selectOption('Java');
await page.locator('#country').selectOption('India');

await show(page);
await browser.close();
```

**Output**

The screenshot shows Java in the Skills dropdown and India in the Select Country dropdown.

**Explanation:** The Skills dropdown has 78 options and holds one pick at a time. If you select
Java and then Python, only Python remains. Two dropdowns on this page mention a country. The one
under the Country heading, with the id `countries`, contains only the text Select Country and no
countries, so `selectOption` on it waits and then fails. The one under Select Country, with the id
`country`, contains 11 countries, including India.

## The same actions in a spec file, with an assertion

[Week 1 - Day 5 - Fundamentals](/learn/w1/d5/p2) showed that a test without an assertion passes
whether or not its steps worked. A test that fills a form needs a check on the form. `toHaveValue`
is an assertion that checks the text a field holds. In the `tests` folder, create a file named
`register.spec.ts`, and paste this code into it:

```ts
import { test, expect } from '@playwright/test';

test('the registration form takes every kind of control', async ({ page }) => {
  await page.goto('https://demo.automationtesting.in/Register.html');

  // Fill the text fields.
  await page.getByPlaceholder('First Name').fill('Ada');
  await page.getByPlaceholder('Last Name').fill('Lovelace');
  await page.locator('textarea').fill('12 Engine Street');
  await page.locator("input[type='email']").fill('ada@example.com');
  await page.locator("input[type='tel']").pressSequentially('5551234567');

  // Check one radio button and two checkboxes.
  await page.getByLabel('FeMale').check();
  await page.locator('#checkbox1').check();
  await page.locator('#checkbox3').check();

  // Pick one option in each dropdown.
  await page.locator('#Skills').selectOption('Java');
  await page.locator('#country').selectOption('India');

  // Check that two of the fields hold the values that the steps entered.
  await expect(page.locator("input[type='email']")).toHaveValue('ada@example.com');
  await expect(page.locator('#country')).toHaveValue('India');
});
```

In the integrated terminal, run the new file in Chromium only:

```bash
npx playwright test tests/register.spec.ts --project=chromium
```

**Output**

```output
Running 1 test using 1 worker

  1 passed (3.8s)
```

**Explanation:** The two `expect` lines are what make this a test. If the Email field held a
different value, or the country had not been picked, the test would fail and print the expected and
received values. `toHaveValue` retries for up to five seconds, like `toHaveURL` and `toBeVisible`,
so it also works when a field takes a moment to update. Your time may be different.

## Best practices

- Use `fill()` for text, and `pressSequentially()` only when a field reacts to each keystroke.
- Find a control by its placeholder, role, or label when it has one, and by a selector only when it
  has none.
- Read the exact text on the page before you write it into a locator, because `FeMale` is not
  `Female`.
- End every spec file with at least one assertion on the form, so that a step that went wrong makes
  the test fail.

## Common mistakes

| Mistake | What you see | Fix |
|---|---|---|
| Wrote `getByLabel('Male')` for the first radio button | An error that says the locator resolved to 2 elements, because Male also matches FeMale | Write `getByLabel('Male', { exact: true })`. |
| Used `#countries` for the country dropdown | `selectOption` waits, and then fails with a timeout | Use `#country`, the dropdown that holds the countries. |
| Selected two skills, expecting both to stay | Only the last pick is shown | Pick one skill. This dropdown holds one option at a time. |
| Wrote `.type()` from an older tutorial | VS Code draws a line through `type` | Write `pressSequentially()`, or `fill()` when the field does not react to each key. |
