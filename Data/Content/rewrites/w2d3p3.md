# Week 2 - Day 3 - Implementation - A helper that returns a unique email

A **helper** is a function that several tests call, kept in a file of its own. This lesson adds one
to the helper file from [Day 1 - Implementation](/learn/w2/d1/p3), so that no test repeats the line
that builds an email.

## The problem with the Fundamentals version

The test in [Fundamentals](/learn/w2/d3/p2) builds its email with
`'learner' + Date.now() + '@example.com'`. Every test that registers a user needs the same line. If
ten tests each contain it, and the application starts to reject long emails, you change ten lines.
If the line is in one function, you change one line, and every test gets the change.

## Step 1: Add the function to the helper file

Open `tests/registration-helpers.ts` and add this:

```ts
// Return an email that differs on every call.
export function uniqueEmail(): string {
  return 'learner' + Date.now() + Math.floor(Math.random() * 1000) + '@example.com';
}
```

**Explanation:** `export` makes the function available to any file that imports it, as it does for
`fillRegistrationForm` in the same file. `: string` after the parentheses is the **return type**,
which states that the function gives back text. The value is built inside the function, so each call
runs the line again and gets a new email. The random digits after the time are there because
Playwright runs tests at the same time, and two tests can start in the same millisecond.

## Step 2: Use the function in a test

In the `tests` folder, create a file named `unique-helper.spec.ts`, and paste this code into it:

```ts
import { test, expect } from '@playwright/test';
import { fillRegistrationForm, uniqueEmail } from './registration-helpers';

test('the first test registers with its own email', async ({ page }) => {
  // Call the helper once, and keep its result.
  const email = uniqueEmail();
  console.log('email:', email);
  await fillRegistrationForm(page, email);
  await expect(page.locator("input[type='email']")).toHaveValue(email);
});

test('the second test registers with a different email', async ({ page }) => {
  const email = uniqueEmail();
  console.log('email:', email);
  await fillRegistrationForm(page, email);
  await expect(page.locator("input[type='email']")).toHaveValue(email);
});
```

In the integrated terminal, run:

```bash
npx playwright test tests/unique-helper.spec.ts --project=chromium
```

**Output**

```output
Running 2 tests using 2 workers

[chromium] › tests\unique-helper.spec.ts:4:5 › the first test registers with its own email
email: learner1790135003446709@example.com

[chromium] › tests\unique-helper.spec.ts:12:5 › the second test registers with a different email
email: learner1790135003508186@example.com

  2 passed (4.3s)
```

**Explanation:** Both tests import `uniqueEmail` and `fillRegistrationForm` from the same file, and
neither test contains the line that builds an email. The two printed emails differ, although both
tests ran at almost the same moment, because each call of `uniqueEmail()` builds a new one. Each
test keeps its email in a `const`, passes it to `fillRegistrationForm`, and then asserts against the
same `const`. Your time and your number of workers may be different.

## Why it is shaped this way

| Choice | Reason |
|---|---|
| The email is built inside the function, not in a `const` at the top of the file | A `const` at the top of the file is computed once, when the file loads, so every test would get the same email. |
| The function takes no parameters | Every caller wants the same kind of value, so there is nothing to pass in. |
| The function returns the email instead of filling the field | The test needs the email twice, to fill and to assert, so the function hands the value back and the test decides what to do with it. |
| `fillRegistrationForm` takes the email as a parameter | The helper that fills the form does not decide what the email is, so a test can pass a unique one or a fixed one. |

## What a reviewer looks for

- The line that builds an email appears once, in `registration-helpers.ts`, and in no spec file.
- Each test calls `uniqueEmail()` once, stores the result in a `const`, and uses that `const` for
  both the fill and the assertion.
- The helper file contains no `test()`, and its name has no `.spec`, so Playwright never runs it as
  a test file.
