# Week 1 - Day 3 - Fundamentals - Running tests from the CLI

The **command line**, or **CLI** for command-line interface, means typing commands in a terminal
instead of selecting buttons in a window. In this lesson, you run the example tests in your project from the
command line, read the results, and open the report that Playwright creates.

## The example test file

The project that you created in [Day 2 - Fundamentals](/learn/w1/d2/p2) contains one test file,
`tests/example.spec.ts`. Open it in VS Code. It contains two tests:

| Test name | What it checks |
|---|---|
| `has title` | The Playwright website opens, and its title contains the word "Playwright". |
| `get started link` | Selecting the **Get started** link opens a page with the heading "Installation". |

You do not need to understand the code in the file yet. In
[Day 4 - Implementation](/learn/w1/d4/p3), you paste a test into a new file of your own, and in
[Day 5 - Fundamentals](/learn/w1/d5/p2), you write your first test yourself.

## Running every test

To run every test in the project, open the integrated terminal in VS Code and run:

```bash
npx playwright test
```

**Output**

```output
Running 6 tests using 2 workers
  6 passed (2.4s)
```

**Explanation:** **npx** is a tool that comes with npm. It runs a program that is installed in your
project, here Playwright's test runner. The file has two tests, but the output reports six, because
your configuration file lists three browsers in `projects`. Playwright runs every test once in each
browser: two tests in three browsers make six runs. A **worker** is one copy of the test runner, and
Playwright uses several at the same time to finish sooner. The number of workers and the time will
be different on your computer. If a test fails, the output starts with the failing test's name and
an `Error:` line, and the report opens in your browser by itself.

## Running some of the tests

You rarely need to run every test while you work on one of them. These commands run fewer:

| Command | What it runs |
|---|---|
| `npx playwright test tests/example.spec.ts` | Only the tests in one file |
| `npx playwright test --project=chromium` | Every test, but only in Chromium |
| `npx playwright test --headed` | Every test, with the browser windows visible. With three browsers, a window opens for every run, so add `--project=chromium` to watch one browser. |

The text after the command, such as `--project=chromium`, is called an **option**. Options change
what a command does. Without `--headed`, Playwright runs the browsers **headless**: they work
normally but do not appear on the screen, which is faster.

To run only the Chromium tests, run:

```bash
npx playwright test --project=chromium
```

**Output**

```output
Running 2 tests using 2 workers
  2 passed (697ms)
```

**Explanation:** With one browser selected, each test runs once, so the output reports two tests.

## Opening the report

Your configuration file sets `reporter: 'html'`, so every run also creates a report as a web page.
To open the report of the last run, run:

```bash
npx playwright show-report
```

**Output**

```output
  Serving HTML report at http://localhost:9323. Press Ctrl+C to quit.
```

**Explanation:** The report opens in your browser. It lists every test and its result. Select a
test to see each step that it performed. When a test fails, the report is the best place to find
out what happened, because it shows more than the terminal can. The terminal stays busy while the
report is open: when you are done, click in the terminal and press **Ctrl+C** to get the prompt
back.

## package.json and package-lock.json

Your project contains two files that record its packages. A **dependency** is a package that your
project needs in order to work, such as Playwright.

| File | What it holds | Do you edit it? |
|---|---|---|
| `package.json` | The packages your project depends on, and the range of versions that each one may use | Yes. npm updates it when you install a package, and you can also edit it. |
| `package-lock.json` | The exact version of every package that npm installed, including the packages those packages depend on | No. npm writes it for you. |

The dependencies section of `package.json` looks similar to this:

```json
"devDependencies": {
  "@playwright/test": "^1.63.0",
  "@types/node": "^24.3.0"
}
```

The `^` before a version number means "this version, or any later version with the same first
number", so `^1.63.0` may install 1.64 but never 2.0. The lock file records exactly which version
npm chose. When a teammate runs
`npm install`, the lock file ensures that they install the same versions as you.

## Best practices

- While you work on one test, run only its file. Run every test before you finish.
- Open the report whenever a result surprises you.
- When you share your project, for example with Git, share `package.json` and `package-lock.json`
  together.

## Common mistakes

| Mistake | What you see | Fix |
|---|---|---|
| Ran the command outside the project folder | A question ending `Ok to proceed? (y)`, or `Error: No tests found` | Type `n` and press Enter, open the project folder in VS Code, and run the command in its integrated terminal. |
| Expected two results from two tests | The output reports six | Each test runs once per browser in `projects`. Use `--project=chromium` to run one browser. |
| A test failed | Red output beginning `1) [chromium] › ...` and an `Error:` line | The example tests need an internet connection. Read the `Error:` line, then open the report. [Day 5 - Fundamentals](/learn/w1/d5/p2) shows a failure in full. |
| Edited `package-lock.json` by hand | Teammates install different versions | Let npm write the file. Run `npm install` to update it. |
