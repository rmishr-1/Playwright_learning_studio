# Week 2 - Day 2 - TypeScript - Type inference, or how TypeScript decides a variable's type

TypeScript works out the type of a variable from the value you give it. In
[Week 1 - Day 5 - TypeScript](/learn/w1/d5/p1), every variable had its type written out so you
could see it. TypeScript can work the type out from the value, and from now on the course leaves it
out. This lesson shows why that is safe.

## 1. Where a type comes from

[Week 1 - Day 5 - TypeScript](/learn/w1/d5/p1) wrote `const name: string = 'Leela'`. The
`: string` part is a **type annotation**, which is the type written out by hand after the name.
TypeScript does not need it. It reads the value on the right of `=`, and gives the variable the
type of that value. This is called **type inference**, and it means that `'Leela'` makes `name` a
`string` whether or not `: string` is written.

The example below creates three variables without an annotation, and prints them. Select
**Load into editor**, then select **Run**:

```ts
// No type is written. TypeScript gives each name the type of its value.
const name = 'Leela';
const age = 30;
const greeting = `Hello, ${name}`;

console.log(name);
console.log(age + 1);
console.log(greeting);
```

**Output**

```output
Leela
31
Hello, Leela
```

**Explanation:** `name` is a `string`, because `'Leela'` is text. `age` is a `number`, because
`30` is a number, which is why `age + 1` is `31`. `greeting` is a `string`, because a template
literal always produces text. The types are as fixed as they were in Week 1. If a later line tried
to put a number into `name`, TypeScript would report an error, with or without the annotation.

In VS Code, hovering the mouse over a name shows the type that TypeScript gave it, such as
`const name: string`.

## 2. The same rule for a locator

A locator is a value too, so the rule is the same. When you write:

```ts
const box = page.locator('#checkbox1');
```

`page.locator()` returns a `Locator`, so TypeScript gives `box` the type `Locator`. Nothing in
[Fundamentals](/learn/w2/d2/p2) writes `: Locator` after a variable name, because TypeScript has
already worked it out. The type still does its job. If you spelled a method wrong, such as
`box.chekc()`, VS Code would underline it before the test ran.

Two places in this course still write a type by hand, and for the same reason. A function
parameter, such as `email: string` in `fillRegistrationForm(page: Page, email: string)`, has no
value yet when the function is written. A class property, such as `readonly emailField: Locator`
in [Week 1 - Day 5 - Implementation](/learn/w1/d5/p3), is declared before the constructor gives it
a value. In both places, there is no value to read, so there is nothing to infer from.
