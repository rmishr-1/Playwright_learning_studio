# Week 2 - Day 1 - Implementation - The same actions, in one function

The test in [Fundamentals](/learn/w2/d1/p2) fills the registration form in ten lines. In this
lesson, you move those ten lines into one function in a file of its own, and call it from two tests.
You do every step in VS Code and in its integrated terminal, in your own project.

## The problem with the Fundamentals version

Every test that needs a filled form has to repeat the same ten lines. Two tests hold the lines
twice, and a project with thirty such tests holds them thirty times. If the form gains a field, or
a placeholder changes, every copy needs the same edit. When the lines are written once, in one
function, you edit them once.

[Week 1 - Day 5 - Implementation](/learn/w1/d5/p3) solved the same problem for the sign-in steps
with a class. A form that one function can fill needs less than a class, so this lesson uses a plain
function.

## Step 1: Create the helper file

In the `tests` folder, create a file named `registration-helpers.ts`, and paste this code into it:

```ts
import type { Page } from '@playwright/test';

// Fill the registration form for one person. The email is the only value that changes
// between tests, so it is a parameter. The date of birth and the passwords stay empty.
export async function fillRegistrationForm(page: Page, email: string) {
  await page.goto('https://demo.automationtesting.in/Register.html');

  await page.getByPlaceholder('First Name').fill('Ada');
  await page.getByPlaceholder('Last Name').fill('Lovelace');
  await page.locator('textarea').fill('12 Engine Street');
  await page.locator("input[type='email']").fill(email);
  await page.locator("input[type='tel']").fill('5551234567');

  await page.getByLabel('FeMale').check();
  await page.locator('#checkbox1').check();

  await page.locator('#Skills').selectOption('Java');
  await page.locator('#country').selectOption('India');
}
```

**Explanation:** `import type { Page }` brings in `Page`, the type of a browser tab, and the word
`type` says that this file uses it only to describe the parameter. `export` in front of the function
makes it available to any file that imports it. The function takes the tab to act on and the email
to fill in, and everything else it fills is fixed. The file name ends in `.ts`, not `.spec.ts`,
because it holds no tests. [Week 1 - Day 4 - Fundamentals](/learn/w1/d4/p2) explains why that
ending matters.

## Step 2: Create the spec file that uses it

In the `tests` folder, create a file named `register-helper.spec.ts`, and paste this code into it:

```ts
import { test, expect } from '@playwright/test';
import { fillRegistrationForm } from './registration-helpers';

test('the form is filled for Ada', async ({ page }) => {
  await fillRegistrationForm(page, 'ada@example.com');
  await expect(page.locator("input[type='email']")).toHaveValue('ada@example.com');
});

test('the form is filled for Grace', async ({ page }) => {
  await fillRegistrationForm(page, 'grace@example.com');
  await expect(page.locator("input[type='email']")).toHaveValue('grace@example.com');
});
```

In the integrated terminal, run the new file in Chromium only:

```bash
npx playwright test tests/register-helper.spec.ts --project=chromium
```

**Output**

```output
Running 2 tests using 2 workers

[1/2] [chromium] › tests\register-helper.spec.ts:4:5 › the form is filled for Ada
[2/2] [chromium] › tests\register-helper.spec.ts:9:5 › the form is filled for Grace
  2 passed (3.8s)
```

**Explanation:** The second `import` line takes `fillRegistrationForm` out of the helper file.
`'./registration-helpers'` means the file of that name in the same folder, without its `.ts`
ending. Each test calls the function with its own email, and then checks that the Email field holds
that email. The ten lines that fill the form exist once, in the helper file. Your time and your
number of workers may be different.

## Why it is shaped this way

| Choice | Reason |
|---|---|
| The helper acts, and the test asserts | Each test decides what the correct result is. A helper that checked for Ada's email could not serve the test for Grace. |
| The email is a parameter, and the other values are fixed | The email is the only value that the two tests need to differ. A parameter for every field would make each call as long as the ten lines it replaces. |
| The helper opens the page itself | A test that calls it needs one line to reach a filled form, with no `goto` to remember. |
| The file is named `registration-helpers.ts` | Playwright runs every file whose name ends in `.spec.ts`. This file has no tests, so it must not match that pattern. |

## What a reviewer looks for

- The steps that fill the form are written once, in `registration-helpers.ts`.
- The function is named for what it does, `fillRegistrationForm`, not for the methods inside it.
- The helper performs steps, and every assertion is in a test.
